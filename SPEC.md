# Responsive Variables for Sketch — Technical Specification v1.0

## 1. Цель
Разработать устанавливаемый macOS-плагин Responsive Variables для Sketch 2026.4: менеджер дизайн-токенов по принципу Figma Variables с автоматическим выбором режима по ширине корневого фрейма. Один токен назначается один раз; изменение значения или ширины обновляет связанные слои. Поддержать независимые цветовые темы и архитектуру Primitive → Semantic → Component. Не путать уровни токенов с уровнями Atomic Design: токены являются фундаментом для Atoms, Molecules, Organisms, Templates и Pages.

## 2. Обязательная проверка API до реализации
Изучить актуальную официальную документацию https://developer.sketch.com/reference/api/ и https://developer.sketch.com/reference/action/ и установленный Sketch 2026.4. Создать минимальный диагностический плагин. Проверить доступность событий изменения размеров и документа (включая LayersResized и onDocumentChanged, не считать их сигнатуры или доступность гарантированными), определение корневого Frame, сохранение metadata документа и слоя, изменение текстовых свойств, заливок и обводок, жизненный цикл WebView, Undo/Redo. Записать результаты в docs/API-COMPATIBILITY.md. Не использовать вымышленные API. Предпочитать публичные API. Если автоматическое обновление невозможно, реализовать ручное Apply и явно обозначить ограничение; не считать автоматический режим принятым. Не обещать поддержку Symbols, Libraries и нативных Color Variables до проверки.

## 3. MVP
- Типы Number и Color; коллекции, вложенные группы, режимы, ссылки (aliases), привязки к свойствам.
- CRUD токенов, коллекций и режимов; поиск; переименование без потери ссылок; проверка зависимостей перед удалением.
- Брейкпоинты произвольного количества, начальные 360, 746, 1024 px.
- Независимые Light/Dark темы с назначением на корневой фрейм и темой документа по умолчанию Light.
- Привязки: font size, line height, letter spacing, text color, solid fill color, solid border color. Неподдерживаемые свойства показывать явно.
- Автоматическое обновление при изменении ширины фрейма и значений токенов; ручные Apply Selection и Apply Document.
- Локальное хранение в документе, импорт/экспорт JSON, сохранение после закрытия и открытия.
- Собственная панель плагина, без обещания внедрения в нативный Inspector.

## 4. Модель токенов
У каждого токена стабильный UUID, имя, путь группы, collectionId, тип, описание (опционально), значения по modeId. Значение — literal либо alias на UUID другого токена. Коллекция имеет UUID, имя, axis (static, breakpoint, theme), список режимов. Для MVP все breakpoint-коллекции используют общую шкалу ширины документа, theme-коллекции — общую тему фрейма. Component-коллекция static может ссылаться на адаптивные токены: разрешать ссылку в контексте целевого слоя, а не исходной коллекции. Запретить циклы, несовместимые типы, отсутствующие ссылки, дубли имён внутри группы. Переименование не меняет UUID. При удалении используемого токена блокировать операцию с перечнем зависимостей.

Начальные коллекции: Primitives (static), Colors (theme), Typography, Spacing, Sizing, Radius, Borders (breakpoint), Components (static). Коллекции можно редактировать. Для числовых свойств вне MVP хранение токенов доступно, привязки — нет. Цвета по умолчанию не зависят от ширины. HEX #RRGGBB или #RRGGBBAA, нормализовать формат; Number — конечное число, проверять допустимость на уровне свойства (font size > 0, letter spacing может быть отрицательным).

### Пример JSON (внутренний формат, не заявление о соответствии DTCG)
```json
{
  "schemaVersion": 1,
  "breakpoints": [{"id":"mobile","minWidth":360},{"id":"tablet","minWidth":746},{"id":"desktop","minWidth":1024}],
  "themes": ["light","dark"],
  "defaultTheme":"light",
  "collections":[
    {"id":"p","name":"Primitives","axis":"static","modes":["default"]},
    {"id":"t","name":"Typography","axis":"breakpoint","modes":["mobile","tablet","desktop"]},
    {"id":"c","name":"Colors","axis":"theme","modes":["light","dark"]},
    {"id":"cmp","name":"Components","axis":"static","modes":["default"]}
  ],
  "tokens":[
    {"id":"p1","collectionId":"p","path":"blue/600","type":"color","values":{"default":{"literal":"#2563EB"}}},
    {"id":"p2","collectionId":"p","path":"blue/400","type":"color","values":{"default":{"literal":"#60A5FA"}}},
    {"id":"t1","collectionId":"t","path":"body-xl","type":"number","values":{"mobile":{"literal":16},"tablet":{"literal":18},"desktop":{"literal":20}}},
    {"id":"c1","collectionId":"c","path":"action/primary/default","type":"color","values":{"light":{"alias":"p1"},"dark":{"alias":"p2"}}},
    {"id":"cmp1","collectionId":"cmp","path":"button/primary/bg/default","type":"color","values":{"default":{"alias":"c1"}}}
  ]
}
```
IDs в примере сокращены для читаемости; при создании использовать UUID. Формат привязки отдельно: {tokenId, property, styleIndex?}. Для MVP хранить metadata привязок на слоях, темы на корневых фреймах, коллекции и настройки на документе через подтверждённый Settings API. Экспорт токенов не включает идентификаторы слоёв. Версионировать схему и предусмотреть миграции. Не сохранять данные в облако.

## 5. Алгоритм разрешения
1. Найти верхний экранный Frame, содержащий слой (не ближайший вложенный контейнер). Уточнить через API отличие Frame, Artboard, Group и Symbol; при отсутствии корневого фрейма сообщать об этом и не менять слой.
2. Выбрать максимальный minWidth <= ширины; ниже минимального использовать минимальный режим. Границы: 359→mobile, 360→mobile, 745.9→mobile, 746→tablet, 1023.9→tablet, 1024→desktop.
3. Получить тему корневого фрейма, иначе defaultTheme документа. Режим static — default.
4. Рекурсивно разрешить alias с тем же контекстом ширины и темы, отслеживая посещённые UUID. Не использовать произвольное значение при ошибке.
5. Проверить тип и диапазон свойства, сравнить с текущим значением и записать только при отличии. Не изменять другие свойства.
6. При ошибке оставить текущее значение и показать диагностику. Значения для всех режимов обязательны; при добавлении режима предложить скопировать ближайший/выбранный режим.

## 6. Обновления и безопасность
События ресайза и изменения документа реализовать только после проверки API. Debounce ориентировочно 150–250 мс, объединение повторных событий, защита от рекурсии собственных изменений, кэш контекста фрейма, индекс зависимостей токенов. Не сканировать весь документ на каждый пиксель ресайза. Обновлять только затронутые фреймы/слои. При перемещении слоя в другой фрейм, дублировании и открытии документа пересчитывать контекст. Проверить поведение после закрытия панели и перезапуска Sketch; если слушатель требует открытой панели, явно указать это. Обеспечить корректное Undo/Redo без повторного применения, отменяющего Undo. Если API не позволяет — документировать и предусмотреть безопасный ручной режим. Не модифицировать мастер Symbols, общие Text Styles или Color Variables неявно. Для смешанного форматирования текста и неподдерживаемых заливок пропускать слой с объяснением, пока нет безопасной реализации. При ручном изменении связанного свойства считать токен источником истины; предоставить Unbind, сохраняющий последнее значение. Перед массовой записью валидировать план изменений; при частичном сбое сообщать о нём. Не создавать скрытые фоновые процессы.

## 7. UX
Интерфейс на английском, системная светлая/тёмная тема, доступные подписи и клавиатурная навигация. Окно с левой панелью Collections/Groups, основной таблицей (Name, Type, колонки режимов), поиском, Add variable, Add mode, Import, Export. Ячейки редактируются, Color имеет swatch и HEX, alias выбирается из списка совместимых токенов с отображением итогового значения. Сохранение валидных изменений и обновление зависимостей; ошибки рядом с полем. Вкладка Bindings показывает выделенные слои, доступные свойства, текущий токен и resolved value, режим и тему, Bind/Unbind. Для нескольких слоёв показывать mixed и применять только к совместимым после явного действия. Settings: брейкпоинты, темы, Auto Update, диагностика. Изменение темы выбранного корневого фрейма не меняет другие фреймы. Меню Sketch: Open Variables, Bind Selection, Apply Selection, Apply Document, Toggle Auto Update. Состояния empty/loading/error; не терять введённые данные при ошибке.

## 8. Архитектура проекта
Предпочтительно TypeScript (компиляция в совместимый JavaScript), либо JS с типизацией JSDoc, если toolchain Sketch требует. HTML/CSS/JS для WebView; выбрать поддерживаемый способ создания панели после проверки. Минимум зависимостей, фиксированный lockfile. Разделить чистое ядро и Sketch adapter. Предлагаемая структура:
```
src/core/       # schema, validation, resolver, dependency graph
src/sketch/     # frame context, property adapters, storage, events
src/ui/         # manager, bindings, settings, message bridge
src/commands/   # menu handlers
 tests/         # unit and integration fixtures
 docs/          # compatibility, manual QA, architecture
```
Manifest с уникальным идентификатором, версия 0.1.0, корректные команды и подтверждённые action handlers. Bridge валидирует входящие сообщения, не исполняет произвольный код. Не загружать удалённые скрипты. Скрипты npm test, npm run build, npm run package; итог dist/ResponsiveVariables.sketchplugin и ZIP. README с установкой двойным кликом, обновлением, удалением и использованием. Выбор конкретного bundler обосновать в docs/ARCHITECTURE.md.

## 9. Импорт/экспорт
JSON schemaVersion 1. Импорт предварительно валидировать полностью, включая циклы и типы. В MVP поддержать замену коллекции документа с подтверждением и предварительным отчётом о привязках, которые станут недействительными; не удалять привязки молча. Некорректный импорт не изменяет документ. Экспорт сохраняет ID и aliases. DTCG-совместимый обмен — отдельная задача, не заявлять соответствие без проверки спецификации.

## 10. Критерии приёмки
- В одном документе три корневых фрейма 360/746/1024, один токен body-xl даёт соответственно 16/18/20.
- Изменение ширины 1024→746→360 автоматически даёт 20→18→16 без повторного назначения; проверить при закрытой панели.
- Изменение desktop-значения 20→22 обновляет только desktop-зависимости.
- Вложенный фрейм шириной 200 внутри desktop наследует контекст desktop.
- Light и Dark одновременно работают в разных фреймах; ресайз не меняет тему.
- Primitive→Semantic→Component alias корректно обновляет связанные цвета; цикл и несовместимый тип отвергаются.
- Текст, solid fill и border меняют только назначенное свойство; не затрагиваются другие заливки, обводки, стили и слои.
- Переименование сохраняет привязки; удаление используемого токена блокируется; Unbind сохраняет значение.
- Сохранение, закрытие и повторное открытие документа сохраняет токены, темы и привязки; два документа изолированы.
- Дублирование, перенос слоя, Undo/Redo, повторный импорт, повреждённый JSON проверены.
- Нет бесконечных циклов обновления, зависаний и необъяснимых ошибок. Проверить документ с 1000 связанными слоями, записать реальные замеры и условия, не выдумывать показатели.
- Unit-тесты resolver, границ, aliases, validation, migration; ручной QA в Sketch 2026.4 с фактическим результатом каждого сценария.

## 11. Этапы
1. API spike и отчёт совместимости; минимальный плагин с диагностикой.
2. Чистое ядро, схема, resolver и unit-тесты.
3. Хранение и адаптеры слоёв, ручное применение.
4. UI, коллекции, привязки, темы, импорт/экспорт.
5. Автоматическое обновление, Undo/Redo, оптимизация.
6. QA, сборка, README, список известных ограничений.
После MVP: padding/gap/Stack Layout, sizing, radius, opacity, border width, Symbols/Text Styles, интеграция с Color Variables, Libraries и глобальные коллекции, DTCG export, composite tokens. Не расширять MVP без согласования.

## 12. Инструкция для Codex
Работай в текущем репозитории. Сначала изучи существующие файлы и не перезаписывай пользовательские изменения. Проверь окружение, установленный Sketch и официальные API. Реализуй этапы последовательно, запускай тесты после каждого этапа. При недоступности GUI или API явно фиксируй непроверенные сценарии; не выдавай unit-тесты за проверку в Sketch. Не используй private API без согласования. Не останавливайся на макете UI: нужен устанавливаемый пакет и работающие привязки. В конце предоставь пути к сборке, команды установки, результаты тестов, список реализованных и неподтверждённых функций и инструкцию ручного QA. Автоматический ресайз — ключевой критерий продукта, а не необязательная декоративная функция.
